Reference

Text to audio without the window

KokoroGUI also runs from a terminal, and as an MCP server that an AI agent can call. Both speak a line of text into a WAV, or turn a script into a project you can open in the app and a mixdown you can play. They use the same engines, voices and cache as the app.

01 · StartRun it from the KokoroGUI folder

There's nothing extra to install for the command line. Activate the environment you made for the app and run it from the KokoroGUI folder, because custom_voices/, presets/fx/, cache/ and audio_output/ are all looked up in the folder you start from.

Terminal
python -m kokoro_gui.headless engines
python -m kokoro_gui.headless voices --engine kokoro --lang a
python -m kokoro_gui.headless say "Hello there." --voice af_heart --play stream
python -m kokoro_gui.headless render episode.md --cast Sam=am_adam --cast Ann=af_bella
Commands
CommandWhat it does
enginesLists every engine, whether it's installed and why not, and which one is the default.
voicesLists one engine's voices with their language. --engine picks the engine, --lang one language.
devicesLists what --device takes on this machine, and says whether audio can play.
saySpeaks a short text into one WAV. No project.
renderRenders a script into a .tbaw project and a WAV mixdown.
playPlays an audio file, or a part of it with --start and --end in seconds.
stopStops the detached player (see Playback).

These options work with every command, before or after its name:

Options for every command
OptionWhat it does
--jsonPrints the result, or the error, as one JSON object on stdout.
--quietNo progress lines on stderr.
--deviceauto, cpu or cuda.
--settings PATHReads a config_qt.json for its default engine, its Lexicon and each engine's language, voice and model settings. Nothing else in it counts.
--allow-downloadLets a model download. Without it nothing is fetched.

Models. Downloads are off by default. A model or a Kokoro voice that isn't in the Hugging Face cache yet stops the command with model_not_downloaded, so generate once in the app or pass --allow-download the first time.

Settings. Without --settings, speed, pitch, language and the rest are the app's factory defaults. Your own config_qt.json, Lexicon and character library aren't read.

02 · ScriptsThe tags are the ones the transcript uses

A script is plain text. [Name]: at the start of a line says who speaks from there on, [Name:FX]: adds a saved FX, [Name, overlap:0.3]: starts a line over the one before it, and [pause:1.5] adds seconds of silence. The Tags guide describes each one. Two things differ from Auto-split: a name doesn't need to exist as a character first, and the tags are removed from the project's text.

episode.md
[Sam]: Welcome back.

This is a second paragraph, so it's a second clip.

[pause:1.5]
[Ann:Radio]: Good evening from the tower.
  • Each paragraph of a speaker's block is one clip, and each speaker gets a character and a track.
  • Text before the first tag belongs to a character named Narrator.
  • Clips follow each other with no gap. A [pause:x] is the only silence. The last of two pauses in a row counts, and one at the end of the script does nothing and warns.
  • A speaker the cast doesn't name gets the engine's default voice and a warning. A tag's FX name that doesn't exist is a warning too, and the line plays dry. In the cast it's an error.
  • A .md file loses its Markdown first and keeps its tags. A .txt file and a script on stdin are read as they are.

A script file must be .txt or .md in UTF-8, and the same size limits apply as when you import text in the app.

03 · sayOne text, one voice, one WAV

The text is an argument, or comes from stdin when you leave it out or pass -. By default it's treated as Markdown: headings, links and lists are read as plain sentences, a fenced code block is dropped, and a bare address is read as its site's name. Speaker tags and [pause:x] aren't read out and have no effect here.

say
OptionWhat it does
--engine, --voiceThe engine's id and a voice from its list. A voice that isn't in the list is an error that names the ones that are.
--speed0.1 to 4.
--pitch-12 to 12 semitones.
--plainThe text isn't Markdown, so leave it alone.
-o, --outA new .wav, or - to write the WAV to stdout. Without it the WAV gets a new folder in audio_output/headless/, named after the time and the first words.
--no-saveWrites no WAV, for when you only want to hear it.
--playoff (the default), after or stream.

Generated audio is kept in cache/headless_speak/, so a phrase you repeat with the same voice and settings is read from disk instead of generated.

04 · renderA script becomes a project and a mixdown

The result is a .tbaw and a WAV with the same name in a new folder under audio_output/headless/. The project opens in the app with every clip generated, so you can carry on there: change a word, move a clip, add FX, export.

render
OptionWhat it does
--engineThe engine every speaker uses.
--cast NAME=VOICEGives a speaker a voice. Repeat it for each speaker. Names ignore case.
--cast-file PATHA JSON object of speaker to voice, or to an object with any of voice, speed, pitch and fx_preset. A --cast for the same name wins.
--titleThe project's title and the files' name. Without it the name is the script's first words.
-o, --outThe output folder, made when it's missing.
--channels1 (the default) or 2.
--alignAdds word times from Whisper where the engine gives none (Audio8 and LuxTTS), if the Whisper model is downloaded or downloads are allowed.
--playoff (the default), after or stream.
--update, --discard-sessionSee Updating a project.
cast.json
{
  "Sam": "am_adam",
  "Ann": {"voice": "af_bella", "speed": 1.1, "fx_preset": "Radio"}
}

An FX is applied only when the script or the cast names one. Everything else renders dry.

If a clip fails, or you press Ctrl+C, the output folder is left as it was before. The clips that were generated stay in the working folder under cache/projects/, and the error message says where.

05 · Updating a project--update generates only what changed

render new.md --update show.tbaw rebuilds the project from the new script and saves it in place. A paragraph whose text and voice are unchanged keeps its audio, and regenerated in the result counts the clips the engine made again.

  • Kept. The project's settings, its characters with their colors and variants, the tracks with their mixer settings, and the voice of any speaker the new cast doesn't name.
  • Lost. Edits made to clips in the app, such as moves, fades, takes and per-clip FX. The text is whatever the new script says.
  • Refused. A project with recordings, music, subprojects or guide takes, since a script can't make those again.
  • Unsaved changes. If the app left unsaved work in the project, the update stops with unsaved_session. --discard-session throws that work away. A project open in the app is locked and stops the update with project_locked.

The mixdown next to the project is replaced when the project is inside audio_output/headless/. Anywhere else, a WAV of that name could be yours, so the new one gets a free name. If the update fails, the project and the mixdown are put back.

06 · PlaybackAfter, or while it's being made

--play after plays the finished file. --play stream starts as soon as the first piece is ready and works with every engine. say streams in pieces of about 15 words, render a clip at a time with its pauses. An engine slower than speech leaves a silence while the next piece is made, and a line with an overlap plays after the one before it. The mixdown has the overlap.

A command waits until playback ends. --detach starts it as a process of its own instead, prints that process's id and returns at once. Only one detached player runs at a time: a second one waits, or with --interrupt stops the first. stop ends it. What a detached command would have printed goes to audio_output/headless/player.log.

07 · Output and exit codesMade for scripts to read

stdout holds the result and nothing else: the paths, one JSON object with --json, or WAV bytes with say -o -. Progress, status and warnings are JSON lines on stderr. An error is a line on stderr, or with --json the object {"error", "message", "valid"} on stdout, where valid lists the choices when you picked one that doesn't exist.

The result of say and render holds paths, the duration, the sample rate, the engine, word times where the engine has them, warnings, and whether it played. Never audio.

Exit codes
CodeErrorWhen
0It worked.
2bad_arguments, out_not_allowed, unsaved_sessionSomething you passed is wrong, the output path isn't allowed, or the project has unsaved changes.
3engine_not_installedThe engine's packages aren't there.
4unknown_voiceThe engine has no voice of that name.
5model_not_downloadedA model or voice would have to be downloaded.
6project_lockedThe project is open somewhere else.
7generation_failedThe engine, the mix or the save failed.
130interruptedCtrl+C, or a stop.

Where files may go. --out and --update must lead inside audio_output/headless/ or the folder you started from, with links followed. Network paths, device names and names with a colon are refused. A file that's already there is never replaced, except by --update as described above.

08 · MCP serverLet an agent speak and render

The server speaks MCP over stdio. It needs the mcp package, version 2, in the app's environment:

Terminal
pip install -r requirements-mcp.txt

Your client starts it. It has to start in the KokoroGUI folder, and since many clients have no setting for that, the examples change folder first. Put your own path in, and add the block to your client's MCP configuration.

Windows
{
  "mcpServers": {
    "kokorogui": {
      "command": "cmd",
      "args": ["/c", "cd /d C:\\KokoroGUI && .venv\\Scripts\\python -m kokoro_gui.headless.mcp_server"]
    }
  }
}
macOS and Linux
{
  "mcpServers": {
    "kokorogui": {
      "command": "sh",
      "args": ["-c", "cd /path/to/KokoroGUI && exec .venv/bin/python -m kokoro_gui.headless.mcp_server"]
    }
  }
}

The server runs for as long as the client's session, so a model loads once. It loads on the first call that needs it. Defaults come from environment variables, which most clients let you set in an env block.

  • One call generates at a time, and the next one waits. Playback goes on meanwhile, and stop_playback always gets through.
  • A render reports progress. Cancelling a call, or ending the server, stops its work, unlocks the project and leaves no output.
  • A failure is an error result with {"error", "message", "valid"}, using the error names in the table above.
  • Every path a tool takes, to read or to write, must be inside audio_output/headless/ or the folder the server started in. A script from somewhere else goes in as text.

09 · MCP toolsSeven of them

Tools
ToolArgumentsWhat it does
list_enginesThe engines, whether each is installed, and the default.
list_voicesengine, lang_codeAn engine's voices.
speaktext, engine, voice, speed, pitch, markdown, out, save, play, wait_for_playback, interruptWhat say does. play is stream by default here, and the call doesn't wait for it to finish.
render_scriptscript or path, engine, cast, out, update, discard_session, title, channels, align, play, wait_for_playback, interruptWhat render does. Pass the script's text, or the path of a .txt or .md file. play is off by default.
playpath, start_s, end_s, interrupt, wait_for_playbackPlays a file or a part of it, after what's already queued.
stop_playbackStops what plays and drops what's queued. A render goes on. It doesn't reach a player started with --detach.
playback_statusWhat's playing, for how long, and how much is queued.

interrupt stops what is playing first. Without wait_for_playback, played: true means the audio was queued.

11 · LimitsWorth knowing before a long run

  • A render has no length limit, and the mix is built in memory: about 2 GB for an hour of speech at 24 kHz. A [pause:x] takes memory too, so a mistyped huge one fails only after everything was generated.
  • cache/headless_speak/ grows without a limit. Options > Storage doesn't show or clear it. You can delete the folder whenever nothing is running.
  • A character doesn't store its language. If you render with --settings in one language and open the project in an app set to another, its clips show as stale.
  • A render's working folder stays in cache/projects/ so that an update can reuse it. The app clears it when it closes, unless it's the project you had open.
