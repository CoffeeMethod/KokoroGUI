Generating

  • LuxTTS engine

    LuxTTS is an optional local engine for English speech at 48 kHz. Install requirements-luxtts.txt, choose LuxTTS for a character, and save a reference WAV with at least three seconds of clear speech in Voices. In Voices, Auto-Transcribe fills the transcript of the excerpt LuxTTS uses, and you can edit it before saving. Generation uses saved words, falling back to internal transcription only when no transcript is saved. Save assigns a Reference to the active character on the same engine; Use assigns an existing one. Reference engines show the assigned voice in Settings without a second picker. Sampling steps, guidance scale, time shift, reference duration, reference RMS and Smooth Audio are per-engine settings. Speed is passed to the model. CPU and CUDA follow Options > Device; first use downloads the speech model and its Whisper transcriber. Encoded references are reused in memory; edited transcripts invalidate the encoding and affected clips. Source audio and saved transcripts are included in project bundles. Existing LuxTTS clips become stale once after this update because saved transcript text now enters the segment key; other engines keep their existing keys. LuxTTS uses the shared clip generation, caching, FX and export paths, without native word timings or JIT streaming. Cancellation takes effect between model calls. Audio8 continues to require its reference transcript. See installation, settings and troubleshooting.

  • Generate stale clips in the selection

    The Generate menu has a new entry, "Generate stale clips in selection", for generating chapter 3 without the rest of the book. The selection is the clips your selected transcript text overlaps, or the clip selected on the timeline when no text is selected. The entry is greyed out unless the selection holds a stale clip. A selected subproject isn't generated by it, since a subproject generates through its own block. Clips outside the selection stay stale.

  • A long job tells you when it ends

    A generate or export that ran longer than 10 seconds flashes the taskbar entry and beeps when it ends while another window is in front. Options > "Sound when a long job finishes" turns the beep off and keeps the flash. A job that ends while KokoroGUI is the active window stays silent.

  • Closing the window during a generate asks first

    Closing while a generate runs shows "Cancel the generate and quit" and "Keep working". Cancelling stops the engines, keeps the segments of every clip that finished before the cancel, and then closes the window, still asking Save / Discard / Cancel if the project has unsaved changes. Before, the window closed with the workers still running. An export in progress doesn't ask.

Export and loudness

  • Normalize loudness on export

    The Export dialog has a "Normalize loudness" checkbox, off by default, with a "Target (LUFS)" box (-30 to -5, default -16) and a "True peak ceiling (dBTP)" box (-6 to 0, default -1). The export gets one gain that brings the integrated loudness (ITU-R BS.1770) to the target. If that gain would push the true peak past the ceiling, the gain stops at the ceiling and the target isn't reached. There is no limiter. The status line then reports what the file measures, for example "Measured -16.0 LUFS, -1.2 dBTP", and adds "target not reached: peak-limited" when the ceiling won, with the loudness it did reach. A stereo export reads 3 LU louder than the same signal as mono, because both channels count, so pick the target for the channel setting you export. Per-clip files are not normalized. The three settings are kept per project in project.json, which older versions ignore. Normalizing and measuring need the pyloudnorm package, now in requirements.txt. Without it the row is greyed out.

  • File > Measure Loudness

    Renders the project the way Export would, with the channel setting from the Export dialog, and shows the integrated loudness, true peak, sample peak, RMS, noise floor and length. No file is written, and a clip that is out of date counts as silence, as it does in an export. The noise floor is the quietest tenth of the 50 ms windows, measured as RMS, which is how ACX looks for room tone.

  • A level meter on the transport

    Two thin bars under the play buttons show the left and right output level from -60 to 0 dBFS while the project plays. The bar is the RMS of the last block and the tick is the peak, held for 1.5 seconds. The bar is green below -6 dBFS, amber up to -1 and red above. Both bars are empty when playback is stopped or paused.

Export options

  • The Export dialog has tabs

    The dialog is now four tabs. Audio holds the folder, name, format, MP3 bitrate, sample rate, channels, loudness and range. Extras holds the subtitles, the cue sheet and the per-clip files. Tags holds the file tags and cover image (below). Project file holds the four bundle options. Nothing was removed.

  • MP3 bitrate and sample rate

    An MP3 export can be 128, 192, 256 or 320 kbps constant bitrate, default 192. Before, the encoder always wrote 320. The bitrate box shows only while the format is mp3. MP3 stops at 160 kbps below a 32 kHz sample rate, so at the usual 24000 Hz the choices from 192 up all come out at 160 kbps. The Sample rate box offers the project rate (the default, nothing is resampled), 22050, 24000, 44100 and 48000 Hz. Another rate resamples the finished mix once, before the loudness step, so a normalized file measures what the status line reports. Per-clip files keep the project rate and subtitle times don't change. Both choices are kept per project in project.json, which older versions ignore.

  • A filename template

    The Base filename box takes {project} (the project title, or "Untitled"), {date} (YYYY-MM-DD), {time} (HHMMSS) and {range} (the Range choice, or "full"). {project}-{date} gives My Book-2026-10-02.wav. A token it doesn't know stays as typed. A path in the name is cut to its last part, and <>:"/\|?* and control characters are dropped from the name and from what a token expands to. A line under the box shows the name Export will write, and the template itself is what is remembered, so tomorrow's export gets tomorrow's date.

  • Export asks before it overwrites

    When the file Export would write already exists, a prompt offers Replace, Add number and Cancel. Add number appends " (2)", then " (3)", to the first name that is free, and the subtitle, cue sheet and per-clip files take the same name. Cancel leaves the dialog's choices unsaved. Only the mixdown itself is checked; the other files are replaced as before.

Export presets and chapters

  • Presets for ACX and the podcast platforms

    The Audio tab starts with a Preset box: Custom, ACX (Audible), Apple Podcasts, Apple Podcasts (mono), Spotify and YouTube. Picking one fills the format, bitrate, sample rate, channels, normalize mode and targets, head and tail silence and split choice. Changing any of those fields afterwards puts the box back on Custom. After the export, each file is measured and checked against the preset:

    PresetFills inChecks
    ACX (Audible)mp3, 192 kbps, 44100 Hz, mono, RMS -20 dBFS with a limiter at -3.5 dBFS, 1 s head, 2 s tail, one file per subprojectRMS -23 to -18 dBFS; peak at most -3 dBFS; noise floor at most -60 dBFS; length at most 120 min
    Apple Podcastsmp3, 128 kbps, 44100 Hz, stereo, -16 LUFS, -1 dBTPLoudness -17 to -15 LUFS; true peak at most -1 dBTP
    Apple Podcasts (mono)the same as mono, -19 LUFSLoudness -20 to -18 LUFS; true peak at most -1 dBTP
    Spotifymp3, 128 kbps, 44100 Hz, stereo, -14 LUFS, -1 dBTPLoudness -15 to -13 LUFS; true peak at most -1 dBTP
    YouTubewav, 48000 Hz, stereo, -14 LUFS, -1 dBTPLoudness -15 to -13 LUFS; true peak at most -1 dBTP

    RMS is the whole file's RMS, peak is the largest sample, true peak is the 4x oversampled peak, and the noise floor is the quietest tenth of the 50 ms windows. The numbers come from ACX's audio submission requirements and Apple's audio requirements. A failed check is named with the value and what it needed, for example "Noise floor -52.1 dBFS, needs at most -60 dBFS". Steady noise or a tone with no pauses has no quiet stretch and fails the noise floor check. The status line says "Passed the ACX (Audible) checks", or counts the failures and points to the report. Presets are greyed out without the pyloudnorm package. The chosen preset and the new fields below are kept per project in project.json, which older versions ignore.

  • Normalize by RMS, a peak limiter, and head and tail silence

    A "Normalize by" box next to the loudness fields switches between Loudness (LUFS), as before, and RMS level, with a peak limiter. RMS mode applies the gain that brings the whole file's RMS to "Target RMS" (-40 to -6 dBFS, default -20), then the limiter holds every sample under "Peak limiter" (-12 to 0 dBFS, default -3.5). The limiter looks 10 ms ahead and dips the gain around a peak instead of clipping it, with one gain for both channels, and adds no delay. If the limiter leaves the RMS more than 0.5 dB under the target, the status line says "target not reached: peak-limited". "Silence at start" and "Silence at end" (0 to 10 s) pad the written file after the loudness step. Subtitles and the cue sheet move later by the start silence, per-clip files are untouched, and the measurement is of the padded file, so a very short file reads a little quieter than its target. The padding is digital silence, not room tone.

  • One file per subproject or marker range

    "Split into" on the Audio tab offers One file, One file per subproject and One file per marker range. A choice is greyed out when the project has no subproject, or fewer than two markers. Each file covers one subproject's span, or the time between two neighbouring markers, and is named NN - title.ext in the output folder: the number is the position in time order, the title is the subproject's name or the first marker's name with characters a filename can't hold removed. The base filename and the Range choice aren't used. Each file gets its own subtitles, cue sheet and per-clip files when those are ticked. A clip that falls inside no subproject or marker range isn't exported, and the status line and report say how many. If any of the files already exist, one prompt covers all of them: Replace, or Add number to give each file the first free " (2)" name.

    With the ACX preset, a chapter longer than 120 minutes is cut into NN - title part 1, part 2 and so on, each at the clip boundary nearest before 119 minutes, or at 119 minutes when no clip boundary is near. A single file with the ACX preset isn't cut, and fails the Length check when it runs over.

  • An export report

    After a split export, a failed check, or a warning, a report window lists every file written with its length, loudness, true peak, RMS, noise floor and the checks it failed. The window doesn't block the main one. A single file that passes its checks gets only the status line.

Stems

  • A stem per track or per character, and a dialogue stem

    The Extras tab has a Stems box (None, One per track, One per character) and an "Also a dialogue stem" checkbox. Each stem is the project's mix with only one group of clips in it: a track's clips, or a character's. Music beds make a "Music" stem in the per-character set, and clips with no character make "Unassigned". The dialogue stem is every clip except the music beds, so a bed on its own track and the speech on others come apart cleanly. A subproject counts as dialogue. Muted and soloed-out tracks, and clips that aren't generated, have no stem, and a group with nothing audible writes no file. Stems follow the Range choice, and a split export writes them for each chapter.

    Every stem is the length of the mix and starts at the mix's first sample, so they all line up at 0 in an editor. They are written next to the mixdown as <base>_<stem>.<ext>, for example episode_Alice.wav, with characters a filename can't hold replaced by "_" and a number added when two stems would share a name. A project with timecode turned on also gets its start timecode in each name, as digits without separators: episode_Alice_01000000.wav for a start of 01:00:00:00, or the range's start when you export a range. The audio itself still starts at 0.

    Each stem gets what the mixdown gets, so the stems add up to it: the same resample, the same head and tail silence, the same loudness gain. In RMS mode the limiter's gain, worked out from the whole mix, is applied to every stem as well. Stems aren't measured, and a preset's checks run on the mixdown only. A bed set to duck is ducked by the speech of the whole mix, including speech that isn't in the stem, so the bed stem sounds as the bed does in the mix. The mixer clips each stem at full scale, as it clips the mix, so a mix that goes over 0 dBFS before normalizing won't add up exactly. Every stem is a full-length stereo array in memory while the export runs, so a long book with many characters needs that much more RAM. Both settings are kept per project in project.json, which older versions ignore.

Transcripts and chapters

  • Four transcript formats

    The Extras tab has a "Text files" list. WebVTT writes <base>.vtt with each speaker in a voice span (<v Alice>Hello). "SRT transcript" writes <base>.speakers.srt with Alice: Hello; the plain .srt from "Also write .srt" stays as it was, with no names. The Podcasting 2.0 transcript is <base>.transcript.json, version 1.0.0, a list of segments with speaker, startTime, endTime and body, times in seconds. Plain text is <base>.txt, one line per clip as Alice: Hello, with a blank line wherever the speaker changes.

    Each cue is one clip, in timeline order, with the clip's timeline start and end. Music beds, subprojects and clips that have no audio yet get no cue. A [Name:FX]: tag or a [pause:1.5] marker never appears in the text, and runs of whitespace become one space. A clip with no character has no name. Turn off "Speaker names in the transcripts" to leave the names out of all four files.

  • A chapters file and show notes

    "Podcasting 2.0 chapters" writes <base>.chapters.json, version 1.2.0, with a startTime and a title per chapter. "Show notes with timestamps" writes <base>.show-notes.md, a Markdown list with one line per chapter, - (01:05) Title (1:02:05 from an hour on), and the marker's note indented under it.

    Chapters are the markers, with the marker's name as the title. A project with no marker inside the export uses its subprojects instead, titled by their name. A project with neither gets an empty chapters list and an empty notes file, and the status line says so. The MP3 gets the same chapters as ID3 frames (see Tags and cover art).

  • They follow the export

    A range export starts the times at the range, and drops the markers outside it. Silence at the start moves every time later. A split export writes the set for each file, named after the file, so 01 - Chapter 1.vtt sits next to 01 - Chapter 1.wav. The overwrite prompt checks only the main file, as it does for the subtitles. The choices are stored with the project's other export settings.

Tags and cover art

  • A Tags tab in the Export dialog

    The dialog has a fourth tab, Tags, between Extras and Project file. It holds a "Write tags into the file" checkbox (on by default), Title, Artist, Album / show, Episode / track number, Year, a multi-line Description, a cover image and "Write chapter markers into MP3". An empty Title uses the project's title. The number and year boxes take digits only. The choices are stored per project in export["tags"], and an older project opens with the defaults.

    The genre comes from the preset: Audiobook for ACX, Podcast for Apple Podcasts and Spotify, none for Custom and YouTube. Tags go into the mixdown only. Stems and per-clip files get none. The tab is greyed out when the mutagen package isn't installed, except for an M4B, which ffmpeg tags.

  • Cover image

    Pick a JPEG or PNG with the ... button, or type its path. A 64 px preview shows under it. The file is checked by its first bytes, not its extension, and must be 5 MB or less and on a local drive; a network path is refused. A cover that fails the check is left out, the preview says why, and the export still writes the other tags and ends with a warning. The project stores the path as an absolute path. The picture is not copied into the .tbaw, so a project opened on another machine needs the image at that path or a new pick.

  • Chapters in the MP3

    The same chapters as the chapters file, one per marker, or per subproject when no marker falls inside the export, become ID3 CHAP frames. Each chapter ends where the next starts, and the last ends at the end of the file, including any silence at the end. A range export starts at the range, and silence at the start moves the chapters later. Podcast apps that read ID3 chapters show them as a list. The checkbox is greyed out outside mp3.

  • Split exports

    With "Split into" set, each file's title is its chapter's name (without the number) and its track is n/total, so the Title and Episode boxes are greyed out. Artist, album, year, description and cover are the same in every file. An mp3 in a marker split gets one chapter frame, at 0, since a file runs from one marker to the next.

M4B audiobooks

  • Export an audiobook as one M4B

    The Export dialog's Format box has an "m4b" entry. It writes AAC audio in an M4B file that Apple Books, Audiobookshelf and most phone players treat as an audiobook, with a chapter list, the tags from the Tags tab and the cover image. A new "M4B bitrate" box offers 64, 96 and 128 kbps, 96 by default; 64 is enough for one speaking voice. The choice is stored per project as export["m4b_bitrate_kbps"], and older versions ignore it.

    The app doesn't bundle an encoder. It calls the ffmpeg found on your PATH, and the "m4b" entry only appears while one is found. Install ffmpeg and reopen the dialog to get it. A project saved with M4B opens on WAV when ffmpeg is missing.

  • Chapters

    Each placed subproject becomes a chapter named by its title, and a chapter ends where the next one starts. A project with no subprojects uses its markers instead, and when it has both, the subprojects win. A project with neither gets an M4B with no chapter list. The last chapter ends at the end of the file, including silence at the end. A range export starts its chapters at the range, and silence at the start moves them later. Chapters are always written, even with "Write tags into the file" turned off.

  • Tags and covers without mutagen

    ffmpeg writes an M4B's tags, so the Tags tab works for it even when mutagen isn't installed. The cover goes through the same check as every other format: a JPEG or PNG of at most 5 MB on a local drive. A cover that fails is left out and the export ends with a warning. The "Write chapter markers into MP3" box is greyed out for M4B, and the tab says the chapters are always there.

  • How it fails

    The export writes the mix to a temporary WAV beside the output, runs ffmpeg on it and deletes the temporary files whether ffmpeg succeeds or not. The M4B is written under a temporary name and moved into place at the end, so a failed run leaves an existing file untouched. When ffmpeg exits with an error, the status line says "Export failed" with the last lines it printed. The run is stopped if it takes longer than a minute plus the length of the audio. A split export writes one M4B per subproject or marker range, each with its own chapter. Stems and per-clip files in M4B are encoded one ffmpeg run each and have no chapters.

Editing

  • Split and join a clip at the playhead

    Edit > Split Clip at Playhead cuts the clip under the playhead in two. The S key does the same while the timeline has the focus, so typing an "s" in the transcript or a field never splits anything. Right-clicking a clip block also offers Split here, which cuts at the clicked time instead of the playhead. The cut falls on the first letter of a word: the word under the playhead starts the second half, the next word when the playhead is in a gap, and the second word when the playhead is on the first. A clip without word times is cut in proportion to its characters and moved forward to the next word. The text doesn't change.

    The second half is a new clip with the same character, track, FX and status. It follows the first with no added silence and takes the fade-out. The first half keeps its audio, which no longer matches its text, so it shows as stale. Generating it parks the old audio as a take. The second half has no audio yet. An imported recording splits with its words and audio intact. A clip placed on the timeline (unpin it first), a subproject and a music bed can't be split.

    Edit > Join with Next Clip, or Join with next in the block menu, merges the selected clip (the one under the playhead when nothing is selected) with the clip after it. The two need the same character and kind, with nothing but whitespace between them and no other clip's text. The joined clip keeps the first clip's settings and fade-in and takes the second clip's fade-out. The second clip's audio and takes are dropped, and the joined clip is stale. Each split or join is one undo step.

  • Remove filler words from a recording

    Edit > Remove Filler Words... lists the fillers in the imported recordings of the transcript on screen. Each row shows a few words around the filler, a checkbox and a Play button, which plays that stretch of the recording with 0.3 seconds on each side so you hear the word in its sentence. Check all and Uncheck all are at the bottom, and Remove cuts the checked rows. The status line says how many went.

    Two kinds. "um", "uh", "er", "erm", "ah" and "hmm", with stretched spellings such as "ummm" or "uhh", start checked. A hyphenated word ("uh-huh") and a real word ("err", "umbrella") never match. "like", "you know", "I mean", "sort of" and "kind of" start unchecked, and only match when the speaker set them off: a comma after the phrase, and either a comma before it or the start of a sentence. "So, like, we went" matches. "I like it" and "you know what I mean" don't. Only recording text with a timed word under it is listed, so generated clips, music beds and text you typed into a recording are left alone, and no filler spans two clips.

    Each cut takes the word, the comma after it and one space, so "Well, uh, we went" reads "Well, we went". A filler at the end of a sentence takes the space before it, and the comma before that when a full stop follows ("the store, um." becomes "the store."). The audio goes with the words, the same way deleting them by hand does, and the remaining words keep their times. All the cuts are one undo step: Ctrl+Z gives back every word and its audio.

Each has a Ctrl+Alt version that works in any panel, including the transcript. Space and Ctrl+Space still play and pause, and the Help > Keyboard Shortcuts sheet lists every row under Transport, Timeline and Generate.

    The transport can't play backwards or faster yet, so J jumps back 5 seconds and L only plays. A jump to the previous clip from the first clip goes to 0, and a jump to a marker that isn't there says so in the status line. Delete only removes a music bed (its transcript line goes with it, one undo step); on a speech clip it does nothing, because removing the clip would remove its text. Ctrl+G does nothing while a job runs, and Esc is armed only while a generate runs, so it reaches the transcript and dialogs the rest of the time.

  • Snap to grid, and snapping to markers

    A dragged clip already caught on other clips' edges, the playhead and 0 within 8 pixels. Markers now catch too. A new Snap to grid button in the Timeline header (also G with the timeline focused) goes further: a clip or marker you drop where nothing catches lands on the nearest grid line, the dotted lines that sit at the ruler's labelled ticks. The lines draw darker while it is on. Zooming in moves the lines closer together, so the snap gets finer with it. A marker drag uses the grid only.

    The button is a view setting. It is off by default, it is kept with your other settings and it is never written into the project file.

  • Zoom to fit, and a timeline that zooms out to ten hours

    The Zoom to fit button in the timeline header sets the zoom so the whole arrangement fills the window, and scrolls to the start. The zoom floor is now 0.05 pixels per second instead of 20, so ten hours fit in 1,800 px. The ruler's tick steps reach two hours and its labels read h:mm:ss past an hour.

    Zoomed out, a block narrower than 24 px shows no label, and one narrower than 4 px draws no waveform and never decodes its audio. The 20 px minimum block width shrinks with the zoom below 20 pixels per second, down to 1 px at the floor, so a book's blocks don't pile on top of each other. A block under 20 px wide has no fade handles or FX chip. From 20 pixels per second up nothing changes.

  • Reopening a project returns you to where you left off

    The playhead, the timeline zoom and scroll, the transcript scroll and the selected clip are written to the project's session.json, which is never part of the .tbaw. They are saved two seconds after a zoom or selection change, when you close the project, and when you close the window. Open restores them. A value that is missing or damaged is skipped, and a selected clip that no longer exists is ignored.

    The saved view comes back while the project's working folder under cache/projects/ still exists, which is when you relaunch on the last project. Opening or creating a different project deletes the folders of the other closed projects, and their saved view goes with them. Only the root project is remembered; nothing is written while a subproject is open on the timeline.

Chapters

  • An Outline tab for a book's chapters

    The tab sits after Lexicon in the top-right group. It lists the nested subprojects of the level the timeline shows, in text order, with a status and a length, and a total at the bottom. A chapter is "not started" when it is open and none of its clips has audio, "in progress" when it has stale clips (a chapter you haven't opened this session reads "in progress" too, since the tab doesn't open projects to find out), "done" once its mixdown is current, and "missing" when its file can't be found. A chapter that hasn't been rendered shows its estimated length with a "~" in front, the same estimate its timeline block uses.

    Right-click a chapter for Mark proofed. That sets the status of the chapter's block to Approved, the same status the block menu offers, and the row reads "proofed" for as long as the chapter stays done. Clear proofed sets it back to Generated. Each is one undo step on the parent project, and nothing new is stored in the project file. The menu also has Enter subproject and Generate. Double-clicking a row moves the transcript caret to the chapter's line, which points the docks at that subproject as a click there does, and moves the playhead to its start. The tab only rebuilds while it is showing.

  • Markers as an outline, and a running length

    A project with no subprojects lists its markers instead, each with the time to the next marker (the last one to the end of the arrangement). The total is the whole project's length, with a "~" when any clip in it isn't generated yet. For an episode that isn't split into chapters, that is the running length while you write.

Importing books

  • An import wizard with a section checklist and cleanup rules

    File > Import Text and the Welcome dialog's "New from text file..." read the book and then open a wizard before anything reaches a project. The left side lists the sections, an EPUB's chapters or a PDF's outline entries, with a checkbox and a word count each. A section whose title starts with copyright, contents, table of contents, also by, acknowledgments, about the author or dedication starts unticked, and so does a section under 200 characters that is mostly digits and punctuation. All and None set every box. A plain .txt is one section, and the wizard still opens so the cleanup rules apply to it.

    The right side has one checkbox per cleanup rule and two panes, the selected section before and after the ticked rules. The preview updates 150 ms after a change and shows the first 20,000 characters of a long section. The rules run in this order:

    • Drop page numbers. A line of only digits, a roman numeral in one case ("iv", "XIV"), "Page 12", "Page 12 of 300" or "- 12 -" goes. A word that is also a valid numeral, such as "mix" alone on a line, goes too.
    • Join words split by a hyphen at a line break. "exam-" then "ple" becomes "example". The next line has to start with a lowercase letter, so "well-" then "Known" keeps its hyphen.
    • Join wrapped lines inside a paragraph, off by default. A line break becomes a space unless a blank line follows, the line ends a sentence, or either line is a scene break. It suits PDFs, where every line is a wrap. A heading with no punctuation gets joined to the text under it.
    • Turn a line of only *, #, ~ or em dashes into [pause:1.5] in a paragraph of its own. Auto-split turns the marker into a 1.5 second gap.
    • Collapse three or more line breaks to one blank line.
    • Strip trailing spaces.

    Under the panes, three radio buttons pick the destination: a new project with one subproject per section, a new project with one transcript (the sections joined by a blank line), or the current project at the caret. Fixes

  • The loop region and the monitor choice survive reopening a project

    Open rewrote session.json from scratch, so the loop region and the Dub / Original / Both choice were lost each time a project was reopened from its working folder, including on relaunch. They now carry over when the same file reopens into its own folder.

  • A tag no longer adds length to a clip's estimate

    A clip that isn't generated yet is placed on the timeline by its text length, and Fit to slot learns each character's speaking rate from text length over audio length. Both counted the [Name:FX]: tag and any [pause:x] marker, which the engine never speaks, so a tagged clip looked about 15 characters too long. They now leave the markup out, and so does the dub syllable count in Settings > Clip. Clip audio and cache keys don't change.

  • Two Audio8 presets generating at once keep their own sampling settings

    Audio8's max new tokens, temperature, top P and top K were stored on the engine and set again for each chunk. Two chunks with different settings, running on two worker threads, could swap them, so a chunk generated at the other chunk's temperature. Each chunk now carries its own values into the model call. A clip's cache key never changed, so no clip goes stale.

  • A half-written Audio8 reference encoding is no longer trusted

    The cached encoding of a reference voice is written to a temporary file and renamed when complete. A crash mid-write used to leave a truncated file that the next generate loaded as if it were whole.

  • An old cache entry for a split paragraph is regenerated

    Before 4.0.0-beta.2, the whole-document path could save one paragraph as two or more files in cache/. A hit on such an entry played only the first part. An entry that holds more files than the text now splits into is regenerated, and the extra files are deleted.

  • Previews use their own temporary file

    Preview and the Custom Voice mix preview wrote to a fixed name in the temp folder, kokoro_preview.wav and kokoro_mix_preview.wav. On a shared machine another user could create or link that name first, and two previews in a row wrote the same file. Each preview now gets a fresh file from the system. The next preview deletes the previous one, and so does closing the app.

  • The Voice Reference dock refuses network paths

    A path such as \server\share\x.wav in the reference audio field made Windows connect to that host. Auto-Transcribe and Save now refuse a network path before they look at it, and tell you to copy the file locally. They also refuse a file that isn't a .wav or is over 200 MB.

  • A bad saved layout falls back to the default

    A workspace layout in config_qt.json goes to Qt as raw bytes, and a damaged one could crash the app on launch. A saved layout or window geometry is now checked first. It has to be between 8 bytes and 1 MB and start the way Qt's own save does. If it isn't, the workspace's default layout is used.

  • Lexicon rules show as typed

    A rule such as <b>x</b> was drawn as bold text in the Lexicon list. Both sides of each rule are now shown as plain text.

  • A late transcript doesn't land in the wrong engine's editor

    If you moved the Voices tab to another engine while Auto-Transcribe was running, the finished transcript was still written back to the dock. It is now dropped. The transcription itself keeps running until it finishes, since it can't be stopped partway.

  • run.bat works from any folder

    run.bat now changes to its own folder first, uses the py -3 launcher when there is one, and runs pip and main.py through the virtual environment's python.exe by full path instead of whatever python is first on the path.

  • A huge or malformed book is refused, with the reason

    An EPUB is a zip, and one small file can inflate to gigabytes of text in memory. Import Text and New from eBook now read the zip's directory first and refuse an EPUB with an entry over 50 MB uncompressed, an entry compressed more than 100 to 1, or more than 500 MB in all. They also refuse a file over 500 MB, a PDF over 5,000 pages, and a book with more than 20 million characters of text. The error dialog names the limit that was hit.

  • Importing a book no longer freezes the window

    Import Text and New from eBook read the file on the GUI thread, so a big EPUB or PDF locked the window until it finished. The read now runs on a worker thread. The Transport dock shows "Reading name..." and its Cancel button stops the read between pages and chapters.

  • A damaged settings value no longer stops the app from starting

    A string where config_qt.json expects a number, such as "speed": "fast", raised an error while the docks were built and the app never opened. A value of the wrong type now goes back to its default, and so does a file that isn't a JSON object. The Settings fields and the Audio FX dock clamp a number to the field's range. A saved FX preset is checked the same way: a value of the wrong type is skipped and one outside a slider's range is set to the nearest end of it.

  • config_qt.json is written through a temporary file

    The settings file was written in place, so a crash or a full disk partway through left a truncated file, and the next launch read it as empty and started with the defaults. It is now written to config_qt.json.tmp and renamed over the old file once complete.

Timeline and mixing

  • Pauses between clips

    Clips placed one after another have 0.35 s of silence between them, and 0.9 s across a blank line. Both are in Settings > Project (Gap, Paragraph gap). A clip can override its own gap, and [pause:1.5] in the transcript gives the next clip Auto-split creates a 1.5 s gap. The marker stays in the text and is never read aloud.

  • Tracks appear when a character is used

    A character gets a timeline track the first time you assign it text, and a track with no clips isn't drawn, so a big library doesn't open as dozens of empty lanes. An unused track keeps its mute, fader and pan for when it comes back.

  • Unified track layout

    Settings > Project > Track layout > Unified puts every clip on a few lanes (3 by default) and moves to the next lane each time the speaker changes, so a conversation alternates lanes. Mute, solo, fader and pan then act per lane. Switching back puts each clip on its character's track. Either switch is one undo step.

  • Takes

    Regenerating a clip keeps the old version. Right-click a clip > Take to switch back, or Delete take to drop one. A take recorded from text you've since edited says "old text". Old takes and their audio are saved in the project.

  • Ripple on regenerate

    When a regenerated clip comes back longer or shorter, clips you placed by dragging that sit after it move by the same amount. Right-click a clip > Lock in time to keep it where it is, or turn ripple off in Settings > Project. Clips that overlap on one track get a red border.

  • Mixer

    Each track has mute, solo, a fader, a pan slider and a volume automation lane. The A button shows the lane: double-click adds a point, drag moves it, right-click deletes it, Alt-drag moves a segment. Clips have fade-in and fade-out handles on their top corners. Settings > Project > Auto-crossfade adds a 10 ms fade where clips overlap. Playback and export are stereo, and export follows mute, solo, pan, fades and automation.

  • Markers and loops

    Right-click the ruler to add a marker, and drag a flag to move it. Shift-drag on the ruler, or use "Loop to next marker", to loop a region. Export can write just the stretch between two markers.

  • Timecode

    Settings > Project > Timecode shows the ruler and the transport clock as HH:MM:SS:FF at a frame rate you pick, drop-frame included, from any start time.

  • Convolution reverb

    Audio FX > Spatial & Time > Convolution Reverb puts a clip in a recorded space. Pick an impulse response and set Mix (default 0.5). "Add..." copies a .wav into the impulse response library (presets/fx/ir/). Save bundles every impulse response the project uses, and a project's own copy wins over the library's. A missing one, or one longer than 30 seconds, plays dry and logs a warning.

Dubbing and subtitles

  • Subtitle import

    File > Import Subtitles... reads SRT, WebVTT and ASS/SSA files. Each cue becomes its own paragraph at the end of the transcript and a clip locked in time at the cue's start, with the cue's text as the clip's source text and the cue's length as its target.

    When the file names speakers (an ASS Name field, a VTT <v Name> tag), a dialog asks once which character voices each: the narrator, a new character named after the speaker, or one you already have. Cancel imports nothing, and one undo removes the whole import, including the characters it made. Ripple never moves a cue. Dragging one moves it and it stays locked.

  • Locked clips line up on their first word

    Settings > Project > "Align locked clips to their first word" starts a locked clip a little early, by the silence before its first word, so the word lands on the clip's time instead of the breath before it. It's on by default in a project with a locked clip, and skipped for a clip with Trim Silence on.

  • Target durations and Fit to slot

    Settings > Clip > Target (s) gives a clip a length to fill, and subtitle import sets it from each cue. The timeline draws that slot as a bracket, puts how full it is in the clip's label as a percentage, and tints the clip amber past 103% and red past 115%.

    Right-click > Fit to slot changes the clip until it's within 3% of the target. Kokoro regenerates it at a new speed (0.7x to 1.6x, up to three tries). Audio8 has no speed control, so it time-stretches on playback (0.87x to 1.15x). A line still too long at that limit is marked Needs rewrite. Each fit is one undo step. "Fit all over slot" above the timeline, shown once any clip has a target, fits every clip that runs long.

    While you type, a stale clip whose text reads longer than its target gets a wavy amber or red underline, judged from how fast each character has spoken in this project.

  • Original dialogue to dub against

    File > Import Source Track... copies the original recording into the project. Settings > Clip > Original (s) holds the part of it a clip dubs (start - end), and subtitle import fills it from each cue's times. The transport's Dub / Original / Both switch picks what you hear: the dub, the original under each clip, or both at -6 dB each, switchable mid-play. It stays on Dub, greyed out, until the project has a source track.

    Settings > Project shows the source track, a Source offset (where the cue times start in the file) and Remove. Export is still the dub alone.

  • Reference video

    File > Load Video... (MP4, MOV, MKV, WebM, AVI, M4V) opens a Video tab beside Settings that plays the video muted and follows the transport's play, pause, stop and seek. Its Offset box sets which video time sits at the timeline's 0. Workspace > Simple hides the tab.

    The project keeps the video's path, relative to the .tbaw when it can, and asks you to find the file if it has moved. "Bundle the reference video in the project file" in the Export dialog puts the video inside the .tbaw instead (off by default). Save only copies a video you picked with Load Video on this machine. A project someone sent you keeps the copy it came with.

  • Source text

    A clip can carry the original line it's dubbing. It shows in the transcript gutter's tooltip and next to a rough syllable count of both lines.

  • Review

    Each clip has a status (to do, generated, approved, needs rewrite) and a note, set from the clip's right-click menu or Settings. The timeline's Show filter dims the rest. Export can write a cue sheet (.csv) with times, character, source text, text, status and note.

  • Word timing

    Generated clips remember when each word is spoken. Kokoro reports its own timings in English. Audio8 and Kokoro's other languages get a Whisper pass after generating. During playback the transcript highlights the current word, Ctrl+click on a word jumps there, and export can write one subtitle per word.

Imported audio

  • Music beds with ducking

The transcript comes from Whisper (in the background, with progress) or from an SRT, VTT or ASS caption file, optionally with "Refine word timing with Whisper". A review step lists each clip with a play button, and a corrected word keeps its place in the recording. You pick one speaker for the whole recording from your voice-cloning characters, or "Unknown speaker". A caption file's speaker names go through the same mapping dialog as subtitles.

Text and generation

  • The Lexicon applies to timeline clips

    Before, only whole-document and JIT generation used it. Adding or removing a rule now marks the clips whose text it rewrites as stale, and no others.

  • Text splits at natural pauses, toward a word count

    Settings > Target Words per Segment (default 40) replaces Split By. Each piece ends at the strongest boundary near the target: a paragraph, then a sentence end, then a pause (comma, semicolon, colon, dash, line break), each with its own on/off switch. A sentence is only cut when it runs past twice the target, and a word never is. Each piece is one file and one subtitle cue, so a long paragraph no longer leaves a clip stale forever.

  • Transcript details show segments, gaps and clip status

    Options > Transcript details > Show details (off by default) adds overlays to the Transcript panel, each with its own toggle in the same menu. Segment boundaries: each segment of a clip alternates between the character's tint and a lighter one; a grey bar marks a cut at a pause and an amber bar a forced cut between two words, where the voice resets mid-phrase. A stale clip shows the segments Generate will make and updates as you type. Hover a segment for its number, word count, what it ends at, and its length and take (an estimate while stale). Clip info: a status dot and the clip's length in the gutter, and a line under the editor for the clip under the caret: character, engine and voice, segment, length, take, status and gap. Lexicon rewrites: a dotted line over text the Lexicon changes, with what it's spoken as in the tooltip. Gaps: the silence before each clip that starts a line, on its boundary rule. These are app settings in config_qt.json; projects don't change.

  • Whisper is the default auto-transcription engine

    The Voices tab's Auto-Transcribe (for Audio8 References) runs Whisper large-v3-turbo locally through faster-whisper (MIT). It asks before the first-use download (about 1.6 GB) and offers another engine instead. Set WHISPER_MODEL in .env to pick a smaller model. python -m kokoro_gui.engine.asr ref.wav whisper --words prints timed words. If you picked Audio8 in the dock before, that choice stays until you change it.

  • Inline tags are no longer spoken

    A clip made from a [Speaker]: or [Speaker:FX]: line, by Generate > Auto-split then generate or by typing the line and pressing Enter, covers its tag. Before, the engine read the tag aloud, and the splitter could make the tag a segment on its own (a name with spaces, such as [Old Man:Big Hall]:, always did). Now every clip's text drops its tags and [pause:x] markers before the Lexicon and the splitter run. The tag stays in the transcript and keeps the character's color, and subtitles and the cue sheet leave it out too. Projects don't change, but a clip whose text holds a tag is marked stale once and needs Generate.

  • A tag's FX applies to its clip

    The FX half of [Alice:Radio]: used to be ignored on clips. Auto-split and the typed-line shortcut now set the new clip's FX preset to Radio, the same as picking it in the Transcript panel's FX box, in the same undo step as the clip. Change it in the Audio FX tab afterwards; editing the tag text doesn't change it. If no preset has that name, the clip is still made with its character's FX, and auto-split names the missing presets in a warning (the typed line says so in the status bar).

Speed

  • Typing and scrolling stay fast in long projects

    The Transcript and Timeline panels no longer recheck every clip on every keystroke, scroll step or repaint. Each clip's stale flag is remembered and rechecked only when its text, character, overrides, segments or the generation settings change. The timeline updates only the clip blocks that changed, and it waits until you pause typing (60 ms) before updating. A waveform is decoded the first time its block scrolls into view. Measured on a 1,500-clip project (about 43,000 words): a keystroke went from 11 s to 17 ms, a scroll step in the Transcript panel from 1 s to 4 ms, a timeline refresh from 8 s to 23 ms, and redrawing the transcript highlights after a settings change from 1.7 s to 15 ms.

  • Options > Force refresh

    Throws away everything the panels remember (stale flags, clip placement, post-processing settings, decoded waveforms, file checks) and rebuilds it from the project. Use it when a panel looks out of date, or after changing a project's files in another program while KokoroGUI kept focus.

  • Files deleted outside the app count when you come back to it

    A segment file deleted by hand still marks its clip stale, but KokoroGUI now notices when its window becomes active again, after Generate, Open, Save and imports, and on Force refresh, instead of on every repaint. Nothing in the project file changes.

  • An FX change no longer freezes a long project

    Changing a project-wide FX value, or the Settings tab's volume, pitch, normalize or trim, used to render every generated clip on the main thread when the transport reloaded, and the window stopped answering until it finished. Two background threads do that work now. A waveform on screen fills in when its render is ready, and the transport reloads once the renders are done, so the old sound keeps playing until then. On a 1,500-clip project with 750 generated clips, the longest freeze after switching reverb on went from 1.7 s to 0.14 s.

  • Undo copies what the edit changed

    Assigning a character to a range, and the timeline's sub-range text replace, saved a deep copy of every clip and run so Ctrl+Z could put them back. They now save the runs around the edit and the clips those runs belong to. In a 1,500-clip project an assignment went from 50 ms to 6 ms and a replace from 47 ms to 5 ms. An edit that reaches more than 50 clips, or a project with imported recordings, still saves everything. Nothing in the project file changes.

Security

  • Private cache and voice folders

    On Linux and macOS, cache/, custom_voices/ and the Audio8 reference folders are created owner-only (0700), and tightened to that if they already exist. A cache/ that belongs to another user is left alone and a per-user one under ~/.cache/kokorogui/ is used instead.

  • Impulse response names with a colon are refused on Windows

    Windows read a convolution reverb name such as a:b (from a project or an FX preset) as a drive-relative path and loaded the impulse response called b. Such a name is now refused there, as it already was elsewhere, and the reverb plays without it.

Tag 4.0.0-beta.14.0.0-beta.1

The rebuild. 3.2.0 was a CustomTkinter form over one kokoro_engine.py. 4.0.0 is a PySide6 app over a transcript with clips, tracks and characters, pluggable engines with a second real one, and projects that live in one file.

The app

  • Qt frontend, the only frontend

    python main.py or run.bat launches a PySide6 window of dockable panels: the transcript, the Settings, Audio FX, Lexicon and Voices tabs, the timeline and the transport, under File / Edit / Options / Workspace menus. Every panel can be dragged, stacked into tabs or floated. Workspace > Advanced / Simple / Reset layout are saved layouts, and Simple hides the timeline so the transcript gets the full height. The CustomTkinter app (gui.py) is gone, and PySide6 is a regular dependency.

  • Welcome screen

    Launch opens the last project, then puts a dialog over it: recent projects (the open one first, Resume as the default button), New project, New from text file, Open other, right-click to drop a row, Clear list, and a details pane with the file's path, modified time, character and clip counts, audio length and engines. Untick "Show at startup" for a silent resume. File > Welcome... brings it up any time.

  • Undo and redo

    Edit > Undo/Redo over a plain-Python undo stack. Typing undoes like a normal text editor. Character and FX assignments and timeline moves have their own history, and Ctrl+Z reverts whichever happened most recently.

  • Dark and light themes

    Options > Theme, dark by default. One palette module feeds the custom-painted widgets, the Qt palette and a stylesheet for every control. The UI font is Segoe UI / Inter / Noto Sans at 10pt, the transcript one point larger. Timeline clips have rounded corners, a waveform in the clip's own darker shade and a black or white label picked by contrast. The default character palette is eight hues at one lightness and doubles as the color picker's presets.

Transcript and timeline

  • A project, not a text box

    The old "generate this text" input is a project: text with clips, tracks and characters layered on top. The transcript is the source of truth and the audio is generated from it, tracked per clip by a hash of what produced it. Generate works on every stale clip in one pass instead of the whole transcript every time. A project with no clips yet still generates the whole transcript at once. Auto-split turns a [Speaker:FX]-tagged transcript (optionally per paragraph) into clips and generates them in one action.

  • Transcript with character highlighting and a live gutter

    Each run is tinted by its character, so you see speaker boundaries without reading the inline [Speaker:FX]: syntax, which turns into a real assignment the moment you finish a tagged line. Character and FX combos above the editor show the caret's clip and reassign the selection or the whole clip. The gutter labels each character or FX change and shows a play button beside each stale clip. Stale text is dash-underlined, and thin rules show where clips end and where Auto-split would cut. Copy and paste carry the character assignment along.

  • A multi-track timeline on a real seconds axis

    One lane per character. Clips sit end to end in text order at their real duration once generated, and at an estimate (dashed outline, no waveform) before. A ruler with a playhead, a fixed track-header column, Ctrl+wheel zoom. Dragging a clip pins it to a time or moves it to another character's track, and dragging it before an earlier clip also moves its text there. Shift+drag inside a clip carves out a sub-range and replaces it with fresh TTS under any character. Each clip has its own FX button.

  • Playback

    Play, pause, stop, click the ruler to seek, a playhead across all lanes, and the transcript highlights and scrolls to the clip being played. Space toggles playback anywhere but the text editor, and Ctrl+Space toggles it everywhere. One sounddevice stream mixes the timeline in its callback, so the position is sample accurate. Loop toggle included.

  • Export

    File > Export mixes every clip down to one file (wav, mp3, flac or ogg) at its timeline position, optionally with a .srt and per-clip files (<base>_001_Narrator.wav). It warns when clips are stale and offers to generate first. The dialog also holds the project's two bundle options: whether to bundle generated audio, and the audio format for new segments.

Settings and FX

  • Settings and Audio FX follow the selection

    Voice, speed, volume, pitch, normalize and trim live in a Settings tab that reads and writes whatever's selected: the project's defaults, one clip's overrides, or a character. Editing a character affects every clip using it unless that clip has its own override. Audio FX works the same way, with a prompt before changing a character several clips share. The timeline's FX button selects the clip and raises the tab.

  • Audio FX are non-destructive

    Clips are generated as raw model output. The FX chain, volume, pitch, normalize and trim are applied when the transport, the export or the timeline waveform reads them. Move a slider, pick an FX, toggle "Apply": you hear it on the next play, and the clip stays generated. A clip with its own FX override counts as FX-on even if its character's FX is off.

  • Characters replace bare presets

    Existing presets/*.json files become characters on first load (one per file, or a single "Default" seeded from your last settings if you had none), each with its own highlight color. Edit > Characters... edits name, color, voice and FX. The preset files themselves are untouched. Output folder, filename and format moved from the Settings tab to Export.

Projects

  • .tbaw project bundles

    A project is one zip file with the text and clips, every generated segment, and every Mix, Reference and saved FX it uses, so it opens on another machine with the same engines installed. Save writes the file in the background and never leaves a half-written project behind. Save As keeps the same working copy. Autosave writes only into the app's own working copy (cache/projects/), so the file on disk is as new as your last Save.

    Closing with unsaved changes asks Save / Discard / Cancel, and after a crash the next open offers to recover the unsaved session, even if the file was renamed or moved. The window title names the project and shows * while it has unsaved changes. A bundle only ever names audio inside itself, and Save never copies a file from outside the project's working copy into it. .json projects from the 4.0 previews still open and are converted on the spot, with a .tbaw written next to the untouched .json.

  • Generation writes once

    A clip's audio lands straight in the project's working copy under a name derived from what produced it, instead of one copy in cache/ and another in the output folder. Regenerating an up-to-date clip (the gutter button) makes a fresh take under a new name. Opening a project made with another version of an engine keeps its clips clean and says so in the status line.

  • Segment cache rekeyed

    Cache entries are keyed on the voice's name and content rather than its path, so the first generate after upgrading from 3.2.0 misses the old cache/ entries.

Engines

  • Pluggable engines

    kokoro_gui/engines/ defines an engine interface (settings fields, voices, capabilities, project hooks) with three registered engines: Kokoro, Audio8 and a sine-tone Dummy that exists to prove the interface isn't Kokoro-shaped. Options > Engine swaps the Settings tab's fields and the Voices tab live. kokoro_engine.py is a slim core backed by a kokoro_gui/engine/ package split by feature.

  • Audio8, a voice-cloning engine

    Audio8-TTS-Preview-0.6b clones a voice from a reference WAV plus a transcript of what's said in it. The Voices tab lets you browse a WAV, auto-transcribe it, edit the transcript and save it under a name that then shows up in the Voice dropdown. It needs transformers and torchaudio, loads with trust_remote_code=True, and downloads from Hugging Face on first use.

  • Auto-transcription for References

    Auto-Transcribe has an engine picker, also runnable as python -m kokoro_gui.engine.asr <wav>. In this release the default was Audio8-ASR-0.1B (CC-BY-NC-4.0, non-commercial). The alternative is Vosk, fully offline and Apache-2.0, which needs a model folder downloaded by hand. Its path lives in VOSK_MODEL_PATH in .env, which the tab's Browse / Save / Reload buttons edit. The reference is converted to the 16-bit mono PCM Vosk requires, whatever format it starts in.
